# Развёртывание на своём сервере

Приложение — статические файлы: HTML, CSS, JS и картинки, всего около 800 КБ.
Никакой базы данных и серверного кода нет, прогресс хранится в браузере
пользователя. Поэтому подойдёт любой веб-сервер и самый дешёвый VPS.

Два обязательных требования:

1. **HTTPS.** Без него браузер не зарегистрирует service worker, а значит не
   будет ни офлайна, ни установки на телефон. По HTTP приложение откроется, но
   станет обычным сайтом.
2. **Свой домен.** Нужен для сертификата. По одному IP-адресу сертификат
   Let's Encrypt не выдаётся.

---

## Вариант 1: Docker и Caddy — рекомендуется

Caddy сам получает и продлевает сертификат, настраивать нечего.

```bash
# на сервере
git clone https://github.com/big-arch/bim-learning-app.git
cd bim-learning-app
echo "SITE_ADDRESS=bim.example.ru" > .env
docker compose up -d
```

Перед этим направьте A-запись домена на IP сервера и откройте порты 80 и 443.
Сертификат выдаётся при первом обращении, это занимает несколько секунд.

Обновление приложения:

```bash
git pull
docker compose restart
```

Файлы подключены к контейнеру томом только для чтения, поэтому пересобирать
образ при обновлении контента не нужно.

Локальная проверка без домена и сертификата: поставьте
`SITE_ADDRESS=:8080` и откройте `http://localhost:8080`.

## Вариант 2: обычный nginx без Docker

```bash
sudo apt update && sudo apt install -y nginx certbot python3-certbot-nginx
sudo mkdir -p /var/www/bim-academy

sudo cp deploy/nginx-site.conf /etc/nginx/sites-available/bim-academy
sudo sed -i 's/bim.example.ru/ваш-домен.ру/' /etc/nginx/sites-available/bim-academy
sudo ln -s /etc/nginx/sites-available/bim-academy /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

sudo certbot --nginx -d ваш-домен.ру
```

Certbot сам добавит блок с сертификатом, редирект с HTTP на HTTPS и задание
на автоматическое продление.

Дальше выгружайте файлы с рабочего компьютера:

```bash
SERVER=user@1.2.3.4 ./deploy/deploy.sh
```

Скрипт сначала прогоняет проверку данных, потом копирует файлы по rsync и
удаляет на сервере то, чего больше нет в репозитории. Каталог `deploy/`,
Markdown-файлы и `.git` на сервер не попадают.

## Что важно в конфигурации

Оба конфига уже это учитывают, но если будете настраивать свой сервер — вот
что нельзя пропустить:

| Что | Зачем |
| --- | --- |
| `index.html`, `sw.js`, `version.json`, `manifest.webmanifest` — без кэша | Иначе обновление не доедет до установленного на телефон ярлыка: браузер продолжит брать старый service worker |
| Тип `application/manifest+json` для `.webmanifest` | Многие серверы его не знают, и тогда ломается установка на телефон |
| Сжатие gzip или zstd | Основной вес — текстовые JS-файлы с уроками, сжимаются в несколько раз |
| Долгий кэш только для иконок | Остальное подключается с `?v=N` и обновляется при смене версии |


## Живая лента RSS — как включить

Раздел «Новости» работает и без настройки: каталог источников и хронология лежат
в приложении и открываются офлайн. Чтобы вдобавок показывались свежие заголовки,
нужно закрыть две вещи.

**Первое: прокси.** Браузер запрещает странице забирать ленту с чужого сайта —
мешает политика CORS. Это ограничение самого браузера, обойти его в коде
приложения нельзя, нужен посредник, который заберёт ленту и отдаст её с
разрешающим заголовком.

**Второе: адреса лент.** У источника надо знать ссылку на RSS.

### Шаг 1. Поднять прокси

Проще всего — Cloudflare Workers: бесплатно, без своего сервера, работает даже
когда приложение лежит на GitHub Pages. Готовый код: `deploy/feed-worker.js`.

1. cloudflare.com → Workers & Pages → Create → Worker
2. Вставить содержимое `deploy/feed-worker.js`
3. Вписать нужные домены в список `ALLOW` в начале файла
4. Deploy — адрес будет вида `https://имя.ваш-аккаунт.workers.dev`

Если приложение уже стоит на своём сервере с Caddy, прокси можно не поднимать
отдельно — достаточно отдавать ленту со своего домена:

```
handle /feed/example {
	rewrite * /rss/
	reverse_proxy https://example.com {
		header_up Host {upstream_hostport}
	}
}
```

Тогда лента становится «своей» и прокси в настройках приложения не нужен вовсе.

> Список разрешённых хостов обязателен в любом варианте. Прокси, пересылающий
> запрос на любой адрес, рано или поздно используют для атак от вашего имени.

### Шаг 2. Указать адрес прокси в приложении

«Ещё» → «Новости» → поле адреса:

```
https://имя.ваш-аккаунт.workers.dev/?url=
```

Приложение подставит адрес ленты в конец строки. Если прокси ждёт адрес в другом
месте, поставьте метку `{url}` — подстановка произойдёт туда.

### Шаг 3. Добавить источники с лентами

«Новости» → «Добавить свой источник» → заполнить название, ссылку на сайт и
ссылку на RSS.

Как найти адрес ленты, если он не указан явно:

- попробовать типовые: `/rss`, `/feed`, `/rss.xml`, `/feed.xml`, `/news/rss`;
- открыть исходный код страницы и поискать `application/rss+xml` — в этом теге
  и будет ссылка;
- у Telegram-каналов лент нет, но публичный канал читается через сторонние
  мосты вида `rsshub` — это отдельный сервис, который тоже надо где-то поднять.

### Шаг 4. Проверить

В «Ещё» → «Новости» нажать «Проверить ленты». Приложение опросит все источники и
покажет итог: сколько лент ответило и сколько записей получено.

Подробности — во вкладке «Новости», блок «Состояние лент». Там по каждому
источнику написано, что именно произошло:

| Что показано | Что это значит |
| --- | --- |
| ✅ 12 записей | Лента работает |
| ⚠️ ответ 404 | Неверный адрес ленты — проверьте ссылку |
| ⚠️ ответ 403 | Хост не добавлен в `ALLOW` прокси |
| ⚠️ ответила, но записей нет | По ссылке не RSS, а обычная страница |
| ⚠️ не отвечает или закрыта политикой CORS | Прокси не задан либо недоступен |

Загруженные заголовки сохраняются на устройстве, поэтому после первой удачной
загрузки лента показывается и без интернета.


## Проверка после развёртывания

1. Открыть `https://ваш-домен/version.json` — версия должна совпадать с
   `version.json` в репозитории.
2. Открыть сайт, зайти в «Курсы» — в заголовке должно быть число уроков и вопросов.
3. В инструментах разработчика на вкладке Application убедиться, что service
   worker зарегистрирован и активен.
4. Отключить интернет и обновить страницу — приложение должно открыться.
5. На телефоне: iPhone Safari → «Поделиться» → «На экран Домой»;
   Android Chrome → меню → «Установить приложение».

## Если обновление не видно на телефоне

Кэш service worker'а поднимается вручную при каждом изменении контента. Если
после `git pull` на сервере в приложении старые данные:

1. Проверьте, что в репозитории поднялись `CACHE_NAME` в `sw.js`, номер версии
   в `version.json` и параметры `?v=N` в `index.html`.
2. Проверьте заголовки: `curl -I https://ваш-домен/sw.js` — должен быть
   `Cache-Control: no-cache`.
3. Крайняя мера на устройстве: удалить ярлык с домашнего экрана и добавить заново.

## Куда ещё можно положить

Приложение статическое, поэтому работает где угодно без изменений:

- **Российские VPS**: Timeweb, Selectel, Yandex Cloud, VDSina, Reg.ru — от
  200–400 ₽ в месяц, чего для этого приложения более чем достаточно.
- **Объектное хранилище с CDN**: Yandex Object Storage, Selectel S3 — дешевле
  VPS, но настройка заголовков и HTTPS сложнее.
- **Бесплатные хостинги статики**: Netlify, Cloudflare Pages, Vercel — HTTPS и
  свой домен из коробки, деплой из репозитория. По сути замена GitHub Pages,
  а не переход на свой сервер.
- **GitHub Pages со своим доменом** — если уйти хочется только от адреса
  `github.io`, достаточно привязать домен в настройках, сервер не нужен.
